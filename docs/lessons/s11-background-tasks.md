# S11：Background Tasks 后台任务

本课在独立 s11 子工程中，以 S10 完整源码为起点增加后台执行与完成通知。入口为 `dev.learnagent.s11.BackgroundMain`，保留 S10 的十八个工具以及 S03 权限与 S04 Hook。

## 1. 为什么需要后台任务

S02 起的 `shell` 是同步的：模型发出命令，循环阻塞到命令结束，最多等 `shell.timeout-seconds`（默认 30 秒）。`mvn package`、`npm install` 这类命令要么超时被杀，要么把超时调大后整个 Agent 干等几分钟，什么也做不了。

S11 把“启动”和“取结果”拆开：

```text
模型 ──background_run──→ 立即返回 bg_1 ──→ 继续读代码、改文件……
                          │
                   后台线程执行命令
                          │ 完成
                          ▼
                    通知队列 ──下一次请求模型前──→ 附加到最新消息 <background-results>
```

| | `shell` | `background_run` |
| --- | --- | --- |
| 返回时机 | 命令结束后 | 立即，返回任务 ID |
| 超时 | `shell.timeout-seconds`，默认 30 | `background.timeout-seconds`，默认 600 |
| 结果送达 | 本次工具结果 | 完成后自动附加到之后的某次请求 |
| 权限 | 硬拒绝 + 逐次确认 | 同 `shell`，启动时确认一次 |
| 生命周期 | 单次调用 | 本次会话，退出时取消 |

## 2. 工具

- `background_run(command)`：在后台线程用独立的 `ShellTool` 执行，工作目录和输出上限与 `shell` 相同，超时单独配置。返回 `已在后台启动 bg_N：命令`。ID 在会话内递增。
- `background_check(id?)`：给出 ID 返回状态和完整输出；省略时列出全部任务。正常情况下不需要调用它，通知会自动送达；它用于查看被截断的完整输出或运行中的状态。

同时运行最多 4 个，每次会话最多启动 20 个，超出时返回工具错误。参数只允许列出的字段。

状态由 Shell 结果决定：`退出码：0` 为 `completed`，命令超时为 `timed_out`，其他退出码或启动失败为 `failed`；会话结束时被终止的为 `cancelled`。

## 3. 通知怎么送达

后台线程结束时把一段通知放入线程安全队列，并立即在终端打印 `后台> bg_1 completed（1234 ms）：命令，下一次请求模型时通知。`。

`ChatLoop` 每次请求模型前取出队列中的全部通知，合并为：

```text
<background-results>
后台任务已结束：
[bg_1] completed，耗时 1234 ms，命令：mvn -q package
退出码：0
……
</background-results>
```

附加到当前最后一条消息末尾。这条消息只可能是本轮的用户输入或本批最后一个工具结果，与 S05 的提醒相同：不新增消息角色，tool 消息的 `tool_call_id` 不变，协议顺序合法。通知随消息保存在历史中，每条只送达一次；单条通知中的输出超过 2000 字符时截断，提示用 `background_check` 看完整结果。

几个时机：

- 模型还在一轮里连续调用工具时完成：附在下一批工具结果之后，模型在本轮就能看到。
- 本轮已经结束、用户还没输入时完成：终端先打印提示，通知等用户下一次输入时附在该输入之后。程序不会自己发起模型请求。
- 本轮第一次请求就失败（S01 起这种情况丢弃本轮）：已取出的通知放回队首，下一轮再送达，不会丢。工具执行后的失败保留历史，通知也随之保留。

## 4. 与其他机制的关系

| 机制 | 行为 |
| --- | --- |
| S03 权限 | `background_run` 与 `shell` 共用硬拒绝规则，其余逐次确认；确认发生在启动时，后台线程不再读终端输入。`background_check` 直接允许 |
| S04 Hook | 两个工具都触发 Pre/PostToolUse；`background_run` 的 PostToolUse 看到的是“已启动”，命令真正结束时不触发 Hook |
| S06 子代理 | 没有后台工具：子代理结束即丢弃，留下的后台结果没人接收 |
| S08 压缩 | 通知进入历史后和其他消息一样可能被微压缩或总结；完整结果仍可 `background_check` |
| S10 任务图 | 可以认领一个任务、后台跑它的构建，等通知后再 `task_complete` |

`ChatLoop` 本课修改了两处，均在 `background` 为 null 时与 S10 完全相同：请求前附加通知；`run` 结束（exit、EOF、中断或异常）时调用 `shutdown` 终止仍在运行的命令，并打印取消数量。

## 5. 局限

- 只在内存中：退出即取消，不能跨会话继续，也不能在 Agent 退出后继续运行。需要持久化的定时执行见 S12。
- 结果只在下一次请求模型时交给模型；空闲时完成不会唤醒模型。
- 启动后无法单独取消某个任务，只能等超时或退出会话。
- 取消通过中断线程并终止可枚举的子进程树完成，脱离进程树的后台子进程可能残留，与 `shell` 相同，不是沙箱。
- 后台提示可能打印在 `你> ` 提示符之后，终端显示会穿插，不影响输入。

## 6. 练习

1. 让模型后台运行 `Start-Sleep 15; Write-Output done`，同时读一个文件，观察两件事并行。
2. 在本轮结束后等通知出现，再输入“结果如何”，观察 `<background-results>` 附在你的输入后。
3. 后台运行一个故意失败的命令，观察 `failed` 和退出码。
4. 把 `background.timeout-seconds` 设为 5，后台运行 `Start-Sleep 20`，观察 `timed_out`。
5. 后台启动一个长命令后立即 exit，确认终端提示已取消，命令的副作用没有发生。

## 7. 验证

自动测试覆盖：启动立即返回、完成后只通知一次、乱序完成按完成顺序通知、放回队列后顺序不变、状态判定（成功、失败、超时）、并发与总数上限、Shell 异常转为失败、未知 ID、关闭后取消且不通知并拒绝新任务、长输出在通知中截断而 `background_check` 保留全文、真实 PowerShell 后台执行与超时、关闭会话不等待长命令且命令副作用未发生；工具参数校验与查看；主循环注册二十个工具、提示词为 S10 加后台规则、通知附加到最后一条 user/tool 消息且不新增角色、只出现一次、首次请求失败后放回下一轮送达、拒绝确认不启动、硬拒绝规则生效、exit 取消运行中的命令、Hook 顺序与拦截、子代理无后台工具；配置默认值与校验。并发测试用可控的假 Shell 决定结束时机。模型是否会在合适时机选择后台执行、等待期间是否做有用的事需真实服务单独验收。
