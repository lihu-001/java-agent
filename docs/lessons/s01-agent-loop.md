# s01：从对话循环到 Agent Loop

S01 按三个步骤理解和练习：对话循环 → 对话加工具 → 工具结果回传后再次请求模型。当前代码实现了第三步的完整循环；前两步是学习顺序，没有单独的运行模式。后续课程继续按步骤推进，每一步观察并验证后再增加下一步能力。

## 第一步：对话循环

先理解一次输入、一次模型请求和历史保留：

```text
读取用户输入 → 携带历史请求模型 → 保存并输出回答 → 等待下一条输入
```

模型接口每次接收一份 `messages`，程序需要主动把之前的对话带上。输入“我叫小李”，得到回答后，再问“我叫什么？”，请求中的消息顺序为：

```text
system：系统说明
user：我叫小李
assistant：你好，小李
user：我叫什么？
```

`ChatLoop` 维护内存中的历史，`ModelClient` 提供模型调用接口，`OpenAiClient` 使用 fastjson2 构造 JSON，再由 JDK HttpClient 发送。重启程序后历史清空。

练习：启动后依次输入“我叫小李，请记住”“我刚才说自己叫什么？”。在 `client.complete` 处设置断点，检查第二次请求中的历史。

## 第二步：对话加工具

在第一步的基础上，增加工具定义和执行器：

```text
用户输入 → 请求模型（附带工具定义）
               ├─ 普通文本 → 展示回答
               └─ 工具调用 → Java 执行工具 → 展示执行结果
```

这一步先观察工具如何执行，不自动把结果交给模型继续处理。当前完整代码在执行完工具后还会进入第三步，可以在 `executeTool` 处设置断点分段观察。

本课只提供 `shell`：

- `ToolDefinition`：告诉模型工具名、用途和参数格式。
- `ToolCall`：模型返回的调用 ID、工具名和参数字符串。
- `ShellTool`：校验参数，用 `ProcessBuilder` 真正执行命令。

例如模型返回的参数为：

```json
{"command":"Get-Content -Encoding UTF8 example.txt"}
```

模型生成的是执行请求，读取文件的是本机 Java 程序。Windows 使用 PowerShell，Unix 使用 `/bin/sh`。默认工作目录为 `playground`，每次工具调用启动独立进程，`cd` 和变量不会跨调用保留。

练习：让模型通过 `shell` 列出练习目录并读取 `example.txt`，观察 `工具请求>` 中的参数和 `工具结果>` 中的实际输出。

## 第三步：回传工具结果，自动继续请求模型

模型第一次请求时还不知道文件内容。Java 拿到工具结果后，需要再次请求模型，让它根据结果回答或决定下一步操作：

```text
用户输入
   ↓
请求模型 ←────────────────────────┐
   ↓                             │
保存 assistant 消息              │
   ├─ 没有工具调用 → 结束本轮      │
   └─ 有工具调用 → 执行工具        │
                     ↓           │
                 追加 tool 结果 ──┘
```

假设读取文件只需一次工具调用，第二次 API 请求中的历史是：

```text
system：系统说明
user：读取 example.txt，说明它的用途
assistant：tool_calls=[id=call-1, name=shell, arguments=...]
tool：tool_call_id=call-1，content=文件实际内容
```

模型可以据此返回最终回答。一次回复也可能包含多个工具调用；程序按顺序执行，每个结果通过 `tool_call_id` 对应原调用，再一起发给模型。

`ChatLoop` 的三个循环各有不同职责：

| 循环 | 职责 |
| --- | --- |
| 外层 `while` | 等待下一条用户消息 |
| 中间 `for (step...)` | 为当前用户消息多次请求模型 |
| 内层 `for (ToolCall...)` | 执行当前模型回复中的各个工具调用 |

`agent.max-model-calls=10` 限制的是每条用户输入最多请求模型 10 次，包含最终回答请求，不是最多执行 10 个工具。第 10 次回复如果还有工具调用，这批工具不执行，但会补齐“未执行”的工具结果并说明终止原因。用户再输入“继续”会开启新一轮计数，已有历史保留。

## 运行与验收

先按 [README](../../README.md) 填写本地 `config.properties`，使用 JDK 17，在项目根目录运行：

```powershell
.\mvnw.cmd package
.\mvnw.cmd -q compile exec:java
```

`package` 会先运行测试再生成普通 JAR。自动测试无需 API 密钥；交互启动会使用本地配置的真实模型。

依次输入：

```text
请调用 shell，列出当前练习目录的文件，用 UTF-8 读取 example.txt，并根据实际内容说明用途。不要修改文件。
刚才读取了哪个文件？请仅依据对话历史回答，不要再调用工具。
exit
```

验收时应看到工具请求、带匹配调用 ID 的执行结果、基于文件内容的最终回答，以及正确的历史追问回答。`exit`、`quit` 或输入结束会退出；空行跳过。

## 失败和限制

- 无效参数、未知工具、命令非零退出码和超时都会形成工具结果，模型可据此继续处理。
- 模型请求失败不会自动重试；尚未记录工具调用的本轮不保存，已经记录的工具调用及结果会保留。
- 模型请求超时为 60 秒；Shell 默认超时 30 秒，最多保留 12000 个输出字符，超出时标记截断。
- 标准输出和错误输出合并。PowerShell 进度输出被关闭，避免首次加载模块的进度 XML 混入工具结果。
- 工作目录不是沙箱。工具使用当前用户权限；许可、上下文压缩及后台任务管理不在 S01 范围内。
