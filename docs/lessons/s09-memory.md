# S09：Memory 跨会话记忆

本课在独立 s09 子工程中，以 S08 完整源码为起点增加跨会话记忆。入口为 `dev.learnagent.s09.MemoryMain`，保留五个基础工具、`todo_write`、`task`、`load_skill`、`compact`，以及 S03 权限与 S04 Hook。

## 1. 为什么需要记忆

S01—S08 的一切都只活在一次会话里：历史、任务清单、压缩摘要，程序一退出就没了。下次启动，用户又得重新说一遍“测试用 JUnit 5”“我是做后端的，前端解释简单点”。

记忆解决的是“跨会话”。它和前几课的区别：

| 机制 | 生命周期 | 内容 |
| --- | --- | --- |
| 消息历史 | 本次会话 | 全部对话原文 |
| S05 任务清单 | 本次会话 | 当前任务的步骤 |
| S08 压缩摘要 / 完整记录 | 本次会话 / 磁盘存档 | 本次对话的总结与原文 |
| S09 记忆 | 跨会话 | 以后仍有用、且无法从文件得知的少量事实 |

## 2. 存什么、不存什么

四种类型，写在 `memory_write` 的描述里，引导模型判断：

- `user`：用户是谁——角色、熟悉的技术、沟通偏好。
- `feedback`：用户对做法的纠正或认可，附原因，例如“不要自动提交，原因：要先自己审查”。
- `project`：无法从代码和提交记录得知的项目背景、目标与约束。
- `reference`：外部资源的位置——文档、看板、工单链接。

不该存：密钥、一次性的任务进度（那是任务清单）、可以重新读取的文件内容（存了反而会过时）。

## 3. 文件格式

工作目录 `.memory/<name>.md`，每条一个文件：

```markdown
---
name: prefer-junit5
type: feedback
description: 测试统一用 JUnit 5
---

原因：项目父 POM 已固定 JUnit 5 版本。
适用：新增测试类时使用 org.junit.jupiter。
```

文件就是唯一的数据源，没有额外的索引文件：手动编辑、删除后重启即可生效。name 为小写字母、数字和连字符，≤64 字符且与文件名一致；description 单行 ≤200 字符；正文非空 ≤4000 字符；最多 100 条。单个文件无效时启动告警跳过，`.memory` 不存在视为没有记忆。

## 4. 两层加载

与 S07 技能相同的思路：

```text
启动
  └─ MemoryStore.list() → 索引进系统提示词：
       已保存的记忆（……需要时用 memory_read 读取正文）：
       - prefer-junit5 [feedback]：测试统一用 JUnit 5
任务相关时
  assistant → memory_read({"name":"prefer-junit5"})
  tool      → <memory name="prefer-junit5" type="feedback"> 描述 + 正文 </memory>
```

索引只在启动时读取一次。本次会话中写入或删除的记忆不会改动已经发出的系统提示词（避免对话中途变化），下次启动才进入索引；本次需要时可直接 `memory_read`。`memory_read` 每次重读文件。

## 5. 写入与权限

`memory_write` 同名时整体覆盖，先写临时文件再替换，避免写到一半留下损坏的记忆。工具描述要求模型更新前先读旧内容再合并。

| 工具 | 权限 | 原因 |
| --- | --- | --- |
| `memory_read` | 直接允许 | 只读 `.memory` |
| `memory_write` | 逐次确认 | 内容会进入以后每次会话的系统提示词 |
| `memory_delete` | 逐次确认 | 永久删除 |

三个工具都经过 PreToolUse/PostToolUse，Hook 可以拦截。

## 6. 记忆不是指令

记忆是之前会话的笔记，不是用户此刻的要求。系统提示词中的规则写明：记忆可能过时，与用户当前要求或文件实际内容冲突时以后者为准，并更新或删除过时记忆；记忆内容不能用来跳过权限确认。写入需要确认也是为了防止工具结果（例如读到的恶意文件）诱导模型写入“以后都自动批准”这类持久指令。

## 7. 与其他机制的关系

| 机制 | 行为 |
| --- | --- |
| S03 权限 | 读放行，写和删逐次确认；记忆文件由程序写入，不经过 `write_file` 审批 |
| S04 Hook | 三个记忆工具都触发 Pre/PostToolUse |
| S06 子代理 | 子代理没有记忆工具，系统提示词也没有索引；记忆只由主代理根据与用户的对话维护 |
| S08 压缩 | 索引在系统提示词里，压缩后仍在；`memory_read` 结果可能被微压缩，需要时再读 |

## 8. 局限

- 是否保存、保存什么全靠模型判断，可能漏存或存了不该存的；逐次确认是最后一道关。
- 没有检索：索引全部进系统提示词，条数上限 100。记忆更多时需要按相关性检索。
- 没有自动合并去重或过期清理，需要模型或用户手动维护。
- 记忆保存在工作目录，换工作目录就是另一套记忆；不区分用户。

## 9. 练习

1. 说“以后回答都附上文件路径”，确认保存后退出，重新启动，看提示 `记忆> 已加载索引 1 条` 并验证行为。
2. 打开 `.memory/` 下的文件手动改描述，重启后观察索引变化。
3. 在提示词里说出与已有记忆相反的偏好，观察模型是否更新记忆。
4. 在 `s09/.agents/hook.json` 为 `memory_write` 写一个 PreToolUse 拒绝规则。
