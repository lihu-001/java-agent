# S07：Skill Loading 技能加载

本课在独立 s07 子工程中，以 S06 完整源码为起点增加技能目录和 `load_skill` 工具。入口为 `dev.learnagent.s07.SkillMain`，保留五个基础工具、`todo_write`、`task`、S03 权限与 S04 Hook。

## 1. 为什么按需加载

把“如何做代码审查”“如何写发布说明”这类操作规范全部写进系统提示词，每次请求都要发送全部内容，技能越多越浪费，也会让模型在无关任务上分心。技能加载分两层：

```text
系统提示词：……可用技能：
- code-review：审查工作目录中的代码……
- release-notes：根据改动说明撰写中文发布说明……
                         │ 任务匹配时
                         ▼
assistant → load_skill({"name":"code-review"})
tool      → <skill name="code-review"> 完整步骤 </skill>
assistant → 按步骤调用 glob、read_file……
```

启动时只读取每个技能的名称和描述（几十字）；正文留在磁盘，模型判断需要时才通过工具读进当前对话。

## 2. 技能文件

技能放在本子项目 `s07/.agents/skills/<name>/SKILL.md`，与启动目录无关：

```markdown
---
name: code-review
description: 审查工作目录中的代码或文本文件……用户要求“审查”时使用。
---

# 代码审查

1. 用 glob 找出……
```

- frontmatter 只支持单行 `key: value`，值可加引号；`#` 开头为注释，未知字段忽略。这是精简解析，不是完整 YAML。
- `name`：小写字母、数字和连字符，最多 64 字符，必须与目录名一致。
- `description`：非空，最多 1024 字符。写清“做什么”和“什么时候用”，模型只凭它决定是否加载。
- 正文：非空，文件最多 64 KiB、严格 UTF-8；返回给模型时最多 12000 字符，超出截断。
- 最多 32 个技能，按目录名排序；单个技能无效时打印 `技能> 跳过 ...` 并忽略，不阻止启动。目录不存在等于没有技能，此时系统提示词与 S06 完全相同。
- `SKILL.md` 若是指向技能目录之外的链接则拒绝。

## 3. 实现要点

| 类 | 职责 |
| --- | --- |
| `skill.SkillFile` | 解析 frontmatter 与正文，校验大小和编码 |
| `skill.Skill` | 只保存名称、描述、文件路径 |
| `skill.SkillCatalog` | 启动时扫描目录、校验、生成系统提示词中的技能目录；`body` 在加载时重新读文件 |
| `skill.LoadSkillTool` | `load_skill(name)`，返回 `<skill name="...">正文</skill>`；未知名称返回工具错误并列出可用技能 |
| `SkillMain` | 组装：主代理八个工具，子代理五个基础工具加 `load_skill` |

正文在每次 `load_skill` 时重新读取，修改技能步骤无需重启；新增、删除技能或修改名称和描述需要重启，因为目录在启动时已写入系统提示词。

`ChatLoop` 未修改：技能目录只是系统提示词的一部分，技能正文只是一个普通工具结果。

## 4. 与权限、Hook、子代理的关系

| 机制 | 行为 |
| --- | --- |
| S03 权限 | `load_skill` 直接允许，只读技能目录；技能里要求的写入、Shell 仍逐次确认 |
| S04 Hook | `load_skill` 触发 PreToolUse/PostToolUse，matcher 可写 `load_skill` 拦截或记录 |
| S05 清单 | `load_skill` 算一批工具，参与未更新提醒计数 |
| S06 子代理 | 子代理系统提示词同样附带技能目录，并有 `load_skill`；它加载的正文只留在子代理历史，主代理只看到总结 |

技能是写给模型的说明，不是程序。技能文本无法授予额外权限，也不会被当作命令执行；但它会影响模型行为，来源不可信的技能与不可信的提示词风险相同。本课没有为技能增加类似 HookTrust 的授权确认。

## 5. 练习

1. 启动后输入：“帮我审查 playground 里的文件。”观察模型先调用 `load_skill`，再按技能步骤输出三级问题列表。
2. 输入：“1+1 等于几？”确认无关任务不会加载技能。
3. 新建 `s07/.agents/skills/translate/SKILL.md`，故意让 `name` 与目录名不同，重启观察跳过告警；改正后再重启。
4. 运行中修改 `code-review` 的正文步骤，不重启，再次要求审查，观察新步骤生效。

## 6. 验证

自动测试覆盖：frontmatter 解析与错误格式、目录缺失、排序与只渲染元数据、各类无效技能跳过且不影响其他技能、数量上限、每次重新读取正文与改名报错、链接越界、示例技能有效；`load_skill` 参数校验、未知名称、截断；系统提示词只有目录而正文作为工具结果出现、免确认但经过 Hook、Hook 拦截、子代理可加载技能但仍无 `task`、无技能时提示词与 S06 相同、无效技能告警但正常启动。全部使用模拟模型与临时目录。模型是否在合适时机主动加载技能，需要真实服务单独验收。
